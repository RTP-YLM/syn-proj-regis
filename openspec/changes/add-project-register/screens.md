## S1 — ProjectRegister ALL (ทุก role)

จุดประสงค์: เห็นภาพรวมทุก Project ทุกทีม (เจตนาเปิดกว้าง — ดู `project-access-control`) + sort/filter

```
┌─ ProjectRegister ALL ────────────────────────────────────────────────────┐
│ [ค้นหา..........] [สถานะ ▾] [ทีม ▾] [Sales ▾] [วันคาดจบ 📅] [ล้าง Filter] │
├──────────────────────────────────────────────────────────────────────────┤
│ # │ Project Code │ หน่วยงาน/โครงการ │ [ทีม ↕] │ [Sales ↕] │ Entry │ [วันคาดจบ ↕] │ สถานะ │      │
│ 1 │ PRJ-2026-07-0001 │ รพ.กลาง /     │ ทีม A  │ sale1    │  3   │ 15/10/26     │ ●นำเสนอ │[Detail]│
│   │ 🏷 Project: open │  จัดซื้อ UPS   │        │          │      │ (เหลือ 88 วัน)│        │      │
│ 2 │ ...                                                                   │
├──────────────────────────────────────────────────────────────────────────┤
│                                        ◀ 1 2 3 ▶   แสดง 10/25/50 ต่อหน้า │
└──────────────────────────────────────────────────────────────────────────┘
```

- **[ทีม ↕] [Sales ↕] [วันคาดจบ ↕]** = หัวคอลัมน์กดเรียง asc/desc (ไอคอน ▲/▼) — ส่งไป server ตาม `project-list-sort-filter`
- **วันคงเหลือ** ติดสีตามเกณฑ์: แดง (<30) / เหลือง (<90) / เขียว — เกณฑ์อ่านจาก `project.notification_config`
- **🏷 Project badge** `open/won/lost/closed` **[ใหม่]** — สถานะระดับ Project (9.22) แสดงคู่กับสถานะ Entry
- คอลัมน์ **Entry** = จำนวน Entry ต่อ Project (aggregate จาก server)
- [Detail] → S7 หน้าเปรียบเทียบ Entry
- สถานะใน dropdown filter มีครบ 13 ค่า รวม "ปิดโครงการ"
- Endpoint: `POST /list`

## S5 — Tab "Project Management" (Sales)

**ยึดตาม `prototype/Template_ProjectManagement.xlsx` (sheet `หลายรายการ`) ไม่ใช่ตารางใน HTML prototype** — ดู `project-management-costing` และ design D12

```
┌─ Project Management ─────────────────────────────────────────────────────────────────────┐
│ ลำดับ│ รายการ  │Brand│Model│Qty│ ต้นทุน │      EP       │ ราคาขาย │      GP      │ ราคาขายคู่แข่ง │
│      │         │     │     │   │ @ │Amt│รายการ│ @ │Amt│ @ │ Amt │ @ │Amt│  %  │ รุ่น│ @ │Amt │
├──────────────────────────────────────────────────────────────────────────────────────────┤
│ ▓▓▓ แถวสรุปโครงการ (เทาเข้ม) — ปี/ชื่อโครงการ/ปีประกัน · ชื่อเซลล์ · ชื่อ Dealer จาก Register        │
│ ▓▓▓ Qty, Amt ทุกช่อง = Σ ของ main item · ทุกช่อง @ = Amt ÷ Qty · GP = ขาย−ทุน−EP (หลังหัก OC) │
├──────────────────────────────────────────────────────────────────────────────────────────┤
│ ▒ 1  │ รายการ/สเปก (เทาอ่อน) │นับ│นับ│  │ Σ ของ spec line ทุกช่อง · GP หลังหัก OC          │  ▒  │
│      │ ├ TE-1K-G3-…   (ขาว)  │Syn │TE-1K│300│4,037.70│ค่าขนส่ง│…│10,000│16,500│…│ GP ก่อนหัก OC │
│      │ ├ Batt 7Ah…    (ขาว)  │First│VT12│300│  884.68│      │  │      │      │  │             │
│      │ └ SNMP         (ขาว)  │     │    │300│2,500.00│  OC  │  │150,000│     │  │  [+ spec line]│
├──────────────────────────────────────────────────────────────────────────────────────────┤
│ ▒ 2  │ … (main item ถัดไป)                                                    [+ main item] │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

- **3 ชั้นตาม template**: แถวสรุป (เทาเข้ม, ระบบรวมให้) → main item (เทาอ่อน, รวมจาก spec line) → spec line (ขาว, ระดับที่กรอกจริง) — ยุบ/ขยายกลุ่มได้เหมือน outline ของ Excel
- **`GP = ราคาขาย − ต้นทุน − EP`** ทุกชั้น, `GP% = GP ÷ ราคาขาย × 100`, `GP @ = GP Amt ÷ Qty` — **ทุกช่อง GP เป็น read-only**
- **OC (Overriding Commission — ค่าคอม Dealer) เป็นรายการหนึ่งใน EP**: แถวขาวโชว์ **GP ก่อนหัก OC** / แถวเทาโชว์ **GP หลังหัก OC** — แยกด้วย flag `ep_item_type.is_oc` ไม่ใช่ข้อความ
- **ช่องที่เป็นยอดรวมทุกช่องคำนวณสดทันทีที่พิมพ์และแก้ด้วยมือไม่ได้** (ไม่ต้องกดปุ่มคำนวณ/ไม่ต้องบันทึกก่อน) — main item ที่ยังไม่มี spec line กรอกเองได้ พอเพิ่ม spec line แรกจะสลับเป็นโหมด auto พร้อมเตือนก่อนทับค่า
- Qty ของ main item = Qty ของ spec line แรก (ไม่ใช่ผลบวก) / Qty แถวสรุป = Σ ของ main item
- ต้นทุนบันทึกวันที่อ้างอิงราคา, EP บันทึกวันที่+แหล่งที่ได้ราคามา (ตาม comment ในไฟล์ template) — ช่อง `รายการ` จะดึงจาก item master ของ ERP ในอนาคต (`9b.22` ยังไม่ปิด รอบนี้พิมพ์เองได้)
- **server คำนวณซ้ำเป็นค่าจริงเสมอและทิ้งยอดรวมที่ client ส่งมา** · ตัวเงิน NUMERIC(18,2)

```
┌─ แก้ไขข้อมูล (Revision ร่าง — Rev 4) ─────────────────────────────────────┐
│ ℹ คำขอแก้ไขที่อนุมัติ: "แก้วันคาดจบและรายการสินค้า" (เหตุผล: ...)              │
│ ⚠ ข้อมูลที่แสดงต่อผู้อื่นยังเป็น Rev 3 จนกว่า revision นี้จะผ่านอนุมัติ           │
├──────────────────────────────────────────────────────────────────────────┤
│ ฟอร์มเหมือน S4/S5 แต่ **เปิดแก้เฉพาะหัวข้อที่ขอไว้** ฟิลด์อื่น read-only        │
├──────────────────────────────────────────────────────────────────────────┤
│                       [บันทึกร่าง]  [ส่งหัวหน้าอนุมัติ Revision]             │
└──────────────────────────────────────────────────────────────────────────┘
```

- เข้าถึงจาก S7 เมื่อ Entry มี revision สถานะ `draft` ของตัวเอง
- ส่งแล้ว Entry → `waitingEdit` (รอบ 2), revision → `waiting`; ถูก reject → กลับมาแก้ที่จอนี้ได้อีก
- Endpoint: `POST /entry-revision/submit`

## S12 — กระดิ่งแจ้งเตือน (navbar — ทุก role)

```
┌─ 🔔 (3) ────────────────────────────────────────┐
│ ⚠ [Event] โครงการ PRJ-...-E2 ถูกปิดแบบ "ล่ม"      │  ← [ใหม่] event จาก project.notification
│   โดย sale7 — 19/07/2026        [ทำเครื่องหมายอ่าน]│
│ ─────────────────────────────────────────────── │
│ ⏰ PRJ-...-E1 เหลือ 12 วันจากวันคาดจบ              │  ← near-due (เรียงใกล้สุดก่อน)
│ ⏰ PRJ-...-E5 เหลือ 45 วัน                        │
│                              [อ่านทั้งหมดแล้ว]     │
└─────────────────────────────────────────────────┘
```

- feed เดียวรวม 2 ชนิด: event (มี read state รายผู้รับ) + near-due (คำนวณสด ไม่มี read state) — `project-notification`
- ขอบเขต near-due ตาม role: Sales = ของตัวเอง / head = ทีมตาม matrix / Manager = ทั้งหมด; ยกเว้น `won/lost/closed` และ Project ที่จบแล้ว
- กดรายการ → เปิด S7 ของ Entry นั้น
- Endpoint: `POST /notification`, `POST /notification/read`

## S13 — หน้าจอ Config (admin) **[ใหม่ — ไม่มีใน prototype ต้องออกแบบตามจอ config เดิมของระบบ]**

|---|---|---|
